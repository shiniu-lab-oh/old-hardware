# 康佳 SDC251 按键接管记录

CT1668 compatibility assumption：先按 TM1668 的 `0x42` 读键协议实验，
显示协议已实测可用，7 个物理按钮的单键按下/松开映射均已确认，
不代表 CT1668 与 TM1668 的全部功能、电气规格或键盘矩阵完全一致。

## 当前测试程序

ESP-IDF 6.0.2；GPIO 和独立 3.3V 供电沿用显示测试接线。
`main.c` 中 `ENABLE_KEY_TEST=1`，优先于其他显示测试。
显示 RAM 保持清空，显示引擎为最低亮度开屏，不执行段位扫描。
每 20ms 读取全部 5 字节；原始日志连续 3 个相同整帧后记录稳定变化。
命名按钮事件按每键独立消抖，连续 3 次相同状态（约 40ms）确认。
7 键均实测为高有效。原始日志保留所有位；命名事件只接受已确认位，
遇到其他位为 1 时保留上次稳定状态、重置待确认计数，不产生 DOWN/UP。

读键帧保持 STB 低：`42` 命令的 8 个时钟，加返回 5 字节的 40 个时钟，
总计 48 个 CLK 上升沿。命令之后 DIO 从输出切为输入，等待至少 5us；
每位在下降沿后等 5us、上升沿后再等 5us 采样；最后先升高 STB，
等待 5us，再恢复 DIO 输出。初始化、清屏帧仍只写 14 字节 RAM。

参考：[Titan Micro TM1668 V1.2 原厂资料镜像，第 2～3 页](https://hubtronics.in/docs/TM1668.pdf)。
TM1668 的返回 DIO 是开漏，资料要求外部 1k～10k 上拉，推荐 10k。
本程序先启用 ESP32 内部上拉协助实验；它不等价于外部上拉。
若读数不稳定或波形上升缓慢，检查板上已有 DIO 上拉。若需补上拉，
连接 DIO 与面板独立电源的 **3.3V**，不改变面板供电电压。

## 操作和日志

打开 `idf.py -p COM5 monitor`，先松开全部按钮。
直接按物理按钮即可看到 `[BUTTON] MENU DOWN`、`[BUTTON] MENU UP` 等事件，
不需要先选择标签。按住不重复产生 DOWN；启动时已按住的键稳定三次后也报告 DOWN。
串口按数字只给后续日志加实验标签，不会模拟物理按键，也不自动确认映射：

| 串口键 | 待测物理按钮 |
| --- | --- |
| 1 | MENU |
| 2 | EXIT |
| 3 | OK |
| 4 | VOL- |
| 5 | VOL+ |
| 6 | CH- |
| 7 | CH+ |
| 0 | 取消标签 |
| r | 打印当前原始值及已稳定值 |
| h 或 ? | 打印帮助 |

无需回车。选好标签后，按住对应物理按钮约 1 秒再松开，重复两次。
先单键测试，组合键和长按重复留到映射确认之后。

- `INITIAL`：首次稳定的原始值，不自动认定所有按钮已松开。
- `CHANGE`：稳定值发生变化。
- `KEYBIT`：变化的 `byte`（数组下标 0～4）、bit、旧值和新值。
- `SAMPLE`：当前未消抖原始样本，每 5 秒或手动按 r 输出。
- `STABLE`：最近一次达到 3 个相同样本的值，可能与当前 SAMPLE 不同。

全 FF 会警告检查回读/接线/上拉，不认定为“所有按钮按下”。全零本身
也不能证明读键成功；必须观察物理按下后可重复变化、松开后恢复。

## 已确认映射

已使用指定的 ESP-IDF 6.0.2 完成无编译警告构建并烧录至 COM5，写入校验通过。
随后只读串口日志观察到 `SAMPLE` 和 `STABLE` 均为 `00 00 00 00 00`。
这仅是当前初始读数，不作为协议成功或全部按钮已松开的证明。
用户已提供按键日志截图，捕获到 4 次相同的置位/恢复循环：

```text
00 00 00 00 00 -> 00 10 00 00 00 -> 00 00 00 00 00
```

变化为 `raw[1] bit4`，掩码 `0x10`，即第 2 个返回字节（数组下标从 0 起）。
4 个循环的日志时间分别为 7150→7690、10550→12430、22290→22970、
25550→26010 ms。这个通道的置位和清零均有稳定变化日志。
截图标签为 UNLABELLED，用户随后明确确认上述操作均为物理 MENU。
因此 MENU 已确认对应 `raw[1] & 0x10`：按下为 1，松开为 0。

EXIT：用户随后提供 `label=EXIT` 的日志，188830→189830 ms、
191690→192930 ms 两次按下/松开均为：

```text
00 00 00 00 00 -> 00 08 00 00 00 -> 00 00 00 00 00
```

EXIT 对应 `raw[1] bit3`，掩码 `0x08`；按下为 1，松开为 0。
OK：用户提供 `label=OK` 的日志，变化为：

```text
00 00 00 00 00 -> 00 01 00 00 00 -> 00 00 00 00 00
```

OK 对应 `raw[1] bit0`，掩码 `0x01`；按下为 1，松开为 0。
截图中记录了 290170→290690、302530→302630、302730→302970、
304450→304670 ms 四个置位/恢复循环。这确认映射，不据此宣称已完成所有消抖场景验证。
用户随后提供其余 4 键各 2 次带名称标签的按下/松开日志，确认：

| 按钮 | 两次按下→松开时间（ms） | 变化 |
| --- | --- | --- |
| VOL- | 376350→376870；380190→380550 | raw[0] bit1，0x02 |
| VOL+ | 415130→415430；421990→422450 | raw[0] bit0，0x01 |
| CH- | 449070→449490；451790→452610 | raw[0] bit3，0x08 |

## 可复用接口

`main/sdc251_keys.h`、`main/sdc251_keys.c` 保存 SDC251 实测映射和消抖状态。
`ct1668.c` 保留原始芯片读写职责，不混入面板按钮名称。

- `sdc251_keys_decode(raw, &pressed)`：把原始 5 字节转换为逻辑按钮掩码，无消抖。
- `sdc251_keys_update(&state, raw, &events)`：每 20ms 调用一次，输出 `held`、`down`、`up` 掩码。
- `sdc251_key_name(SDC251_KEY_MENU)`：返回单个逻辑按钮的名称。

使用 `sdc251_keys_state_t state = {0};` 初始化并持续保存状态；
原始数据仍由 `ct1668_read_keys()` 取得。检测 MENU 新按下使用：

```c
if ((events.down & SDC251_KEY_MENU) != 0) {
    /* Handle one MENU press. */
}
```

逻辑掩码与原始位置分开：MENU/EXIT/OK/VOL-/VOL+/CH-/CH+ 分别使用
逻辑 bit0～bit6。原始已确认位掩码为 `1B 19 00 00 00`。
异常原始位（包括全 FF）返回 `ESP_ERR_INVALID_RESPONSE`，不伪造七键同时按下。
调用方应检查返回值；出错时 events.held 保留旧值，不代表当前硬件状态有效。
原始日志中的 `KEYS`、`KEYBIT` 继续保留，便于诊断。

## 验证范围

实际面板的 7 个单键已分别验证；组合键、鬼键、长按连发尚未做硬件验证。
当前不生成长按事件或自动连发。软件能表达多个同时按下的位，不保证硬件矩阵支持任意组合。
纯 C 映射/事件逻辑通过 `tests/test_keys.py` 的 7 组主机测试，覆盖实测映射、
128 种软件掩码组合、每键独立消抖、按住不重复、松开、启动时按住、
异常帧保留状态并重置消抖、无效参数。组合掩码测试不等于硬件组合键验证。
主机测试只编译执行 `sdc251_keys.c`，不接触 COM5；ESP 错误常量使用测试桩。

2026-09-07 命名事件版本使用 `D:\esp\v6.0.2\esp-idf` 构建通过，
日志无编译 warning/error，应用二进制为 167872 字节。
已烧录 COM5，写入哈希校验通过并复位运行。串口只读验证得到：
